# POMOLOG Phase 2 完了報告

実施日: 2026-10-11。Phase 1.1 (`bfdd192`) と中断時の作業ツリーを引き継ぎ、既存変更を保持して完成・検証した。Firebaseリソース作成・連携、外部公開、課金操作は実施していない。

## 実装内容

- 教科→中項目→小項目をユーザーマスターとして管理。7教科のみを初期登録し、中項目・小項目の登録や選択は任意。全教科をアーカイブした場合は開始を無効にし、教科の追加・復元で再開できる。
- 学習画面と終了確認フォームをIDによる階層選択に変更。親を変えると下位選択を解除し、その親に属する有効な子だけを表示する。学習中の変更でも計測・カウント・メモ・取り消しは維持する。
- 「学習項目管理」を追加。全階層で追加・改名・上下移動・アーカイブ・復元に対応。同じ親の同名項目は、前後空白除去・NFKC正規化で重複を防止する。アーカイブ済み項目も重複判定に含める。
- PCは管理画面を3カラム、スマホは縦並びとし、既存の配色・ロゴ・タイマー優先配置を維持。スマホのナビゲーションは3画面分を独立した行に配置する。
- 7教科の高校基礎テンプレートを教科別に選択して一括追加できる。数学Ⅰ・数学Ａ、英語コミュニケーションⅠ・論理・表現Ⅰなどの一般例を用意した。学習範囲を強制するものではない。
- テンプレート定義はユーザーデータから分離し、定義ID・バージョン・対象レベル・ノードキーを持つ。中学・資格試験を追加可能。同一キー、または同じ親の同名項目を再利用するため、改名・アーカイブ後の再適用でも複製や自動復元はしない。初期教科を改名しても初期IDで対応を維持する。

## 保存形式・移行とデータ保全

v2ではドキュメントに `items` を追加し、項目ごとに `id`、`parentId`、階層、名称、順序、アーカイブ状態、作成・更新時刻、テンプレート由来キーを保存する。記録と進行中セットの `learning` には3階層のIDと表示名スナップショットを併存させる。改名やアーカイブで保存済み記録を変更せず、同じIDを用いて将来の統計・同期で関連付けられる。

初期項目・移行項目・テンプレート項目は名前空間UUID v5、手動追加はランダムUUIDを使用する。移行元に項目の作成・更新時刻がないため、初期・旧項目のマスターメタデータは0とし、元の記録の時刻は変更しない。項目IDは後から改名しても変わらない。

移行は次の順序で実施する。

1. 固定したv1スキーマで検証し、純粋・決定的な変換でマスターと参照IDを生成する。読取りだけでは保存しない。
2. Web Locksによる排他ロックを取得したタブで `prepareForEditing()` を呼び出す。待機タブは移行やバックアップを書き込まない。
3. 元JSONの内容に対応する `pomolog.backup.v1.<UUID>` に原文を退避し、読み戻して一致を確認する。既存の異なる内容は上書きしない。
4. revisionと主データの変更有無を確認し、v2ドキュメントを1回のlocalStorage書込みで保存する。移行確定時だけrevisionを1増やし、再読込み・権限引継ぎでは再移行しない。

旧形式の同じ親の同名項目はまとめ、異なる親では別IDにする。空白や全角・半角を含む元の表示名は各記録にそのまま残す。小項目だけの旧データには管理用中項目「未分類（旧データ）」を補う。セッションID、開始・終了時刻、集中時間、問題数、メモ、通知済みフラグ、取り消し履歴、タイマー状態を保持する。

退避・保存の失敗、不正データ、未知バージョン、退避先の競合、保存中の競合があれば処理を止め、黙って初期化・削除しない。退避後に主データ保存が失敗しても、元の主データと退避原文が残り、再試行できる。移行前原文のキーは自動削除しない。移行後の通常JSONエクスポートはv2マスター・進行中セット・履歴を含む。

アーカイブした親の子は新規選択肢から隠し、子自身のアーカイブ状態を保持する。既に学習中の項目はアーカイブ後も表示して終了保存できる。新しい選択には利用できず、復元は親から順に行う。

- iOS Safari・実機のOS通知・ホーム画面追加は未検証。閉じたブラウザへの通知は既存の保証範囲に含めない。
- 終了確認フォームの未保存の修正は、リロードや画面切替で終了時の保存済み値へ戻る既存仕様を維持。
