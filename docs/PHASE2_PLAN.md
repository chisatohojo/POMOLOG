# Phase 2 設計・実装計画

- v2では学習項目を独立したユーザーマスターとして保存する。項目はID、親ID、階層、名前、兄弟順序、アーカイブ状態、作成・更新時刻、テンプレート由来キーを持つ。
- 記録と進行中セットは3階層のIDと表示名スナップショットを持つ。改名・並び替え・アーカイブで保存済みの記録を書き換えない。集計の関連付けはIDで可能にする。
- 新規作成時は7教科のみ。中項目・小項目は任意。親を変えると下位選択を解除し、親に紐づく有効な項目だけを候補にする。
- 高校基礎テンプレートは教科別に選択して一括追加する。レベル・定義ID・定義バージョン・各ノードキーを持たせ、中学・資格試験を追加できる構成にする。ユーザーマスターとは別ファイルで管理する。
- 追加済みテンプレートのノードキーは改名・アーカイブ後も保持する。同一キーまたは同じ親の同名項目を再利用し、再適用で複製やアーカイブ解除をしない。
- 初期項目・テンプレート項目・旧データ移行には名前空間UUID、ユーザー追加にはランダムUUIDを用いる。移行は純粋・決定的な変換とし、再実行でも同じIDとなる。
- 旧形式の名前は元の記録にそのまま残す。マスターの重複比較は前後空白除去・NFKC正規化で行い、同名でも異なる親の項目は分離する。小項目だけがある旧記録には「未分類（旧データ）」の中項目を補う。
- 読み込みだけでは永続データを変更しない。排他ロック内で元JSONを別キーへ退避し、v2を一度の書込みで保存する。退避失敗・検証失敗なら元データは上書きしない。未知バージョン・不正な親子関係も拒否する。
- 管理画面は教科→中項目→小項目の3カラム（スマホは縦並び）。全階層で追加・改名・上下移動・アーカイブ・復元を用意する。学習中も切り替え可能でタイマー状態は維持する。
- 単体テストでマスター・テンプレート・移行・保存失敗を検証し、ブラウザで選択・管理・学習中の変更・旧データ保持を検証する。既存のタイマー・排他・オフラインテストも維持する。

テンプレートは学習整理用の一般例であり、教科書の全単元や履修範囲を強制しない。科目構成の参考: [文部科学省・高等学校学習指導要領解説](https://www.mext.go.jp/a_menu/shotou/new-cs/1407074.htm)。ID生成の参考: [uuid公式](https://github.com/uuidjs/uuid)。
