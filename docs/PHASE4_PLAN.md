# Phase 4 実装計画

基準: 最新origin/main `612c5a7c6ac037dfbe51e237d54e1686e27073d5`。開始時の作業ツリーはクリーン。`feat/phase4-import-icon` を作成した。

1. 取り込みファイルはサイズ・件数の上限とスキーマを検証する。v1/v2は既存の純粋な移行でv3へ変換し、v3はそのまま検証する。ファイル読み込み・プレビューだけでは保存しない。
2. 追加取り込み＋記録ID重複スキップを採用する。更新日時による上書き・全置換は既存データ保全のため採用しない。削除済みの同じIDもスキップし、古いバックアップから復活させない。新しいIDの削除記録は墓標を保つ。
3. マスターは同じIDを優先し、異なるIDは教科→中項目→小項目の順に階層・統合後の親ID・`normalizeName`で照合する。既存ID・名称・アーカイブ・順序を維持し、対応表で新規項目の親IDと追加記録の項目IDのみ変換する。記録ID・当時の名称は改変しない。テンプレートキーは同じ所有者へ合併し、複数所有を禁止する。候補が曖昧・同一IDの階層／親が不一致・キーが競合する場合は対象を通知して全件中止する。
4. 件数・期間・教科・階層件数・重複・追加・統合・競合・削除済み・進行中データの概要をダイアログに表示する。アーカイブ済み（親を含む）への統合も通知する。元ファイルの進行中タイマーと選択状態は取り込まず、現在の状態を維持する。バックアップ復元も同じ追加方式で行う。
5. 手動JSON書き出しは任意とする。プレビューを固定し、後のrevision変更は最新データでの再確認を要求する。保存時はRepositoryが現在のJSON原文を必ず自動退避・照合してから一度だけ本体へ保存する。ロック・revision検証、保存失敗時の元データ保持を維持する。
6. 原本画像・本体ロゴは保持し、既存シンボルを切り出してfavicon 16/32、Apple 180、PWA 192/512、maskable 512を生成する。HTML・manifest・キャッシュ参照を更新する。
7. 移行・重複・衝突・バックアップ・保存失敗・排他・再読込・アイコン参照・PC/スマホ操作を検証し、全回帰テスト・型チェック・ビルド・整形チェックを実行する。報告、コミット、push、main向けPR作成まで行う。マージ・Firebase操作・サイト公開は行わない。
