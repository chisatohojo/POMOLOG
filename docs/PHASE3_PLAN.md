# Phase 3 設計・実装計画

基準: `63fd17bd2a42fb8da908effc7efb6d28cfaada2a`。最新mainをfetch・fast-forward確認し、`feat/phase3-history-stats` で作業する。

- v3はセッションに `deletedAt: number | null` を追加する。削除・復元もIDと作成日時を維持し更新日時を更新する。物理削除や自動消去は行わない。将来の同期ではこの墓石と更新日時を伝播できる。
- v1→v2の決定的なID移行を維持し、固定v2スキーマを検証してv3へ変換する。原文退避は入力バージョンごとの別キーとし、ロック内だけで一度確定する。中間v2を主データに書き込まない。
- 履歴編集・論理削除・復元をdomain Actionとして実装し、既存Store・Repository・Web Locks・revision検証を使用する。編集フォーム開始時の `updatedAt` も照合し、権限引継ぎ後の古いフォームによる上書きを防ぐ。
- タイマー終了確認と履歴編集は共通フォームで日時・時間・件数を検証する。IDパスを変更しない編集では元の名称を保持する。アーカイブ済みの元項目は保持して保存可能。
- 履歴は開始時刻の新しい順。期間・3階層ID・キーワード・達成判定をAND条件で絞り込む。削除済み一覧から復元する。削除前に確認ダイアログを表示する。
- 日・月・週境界はローカルDateのカレンダー演算を使い、週は月曜開始、範囲は開始以上・次境界未満。24時間・7日分の固定ミリ秒加算は使わない。日付またぎは開始日に全時間を帰属。
- 統計は保存済み・非削除の一意セッションから導出する。問題数0も時間・セット数へ加算し、率は合計正解数÷合計問題数。進行中セットは含めない。項目別キーはIDで、名称は現在のマスターを参照しアーカイブ済みも対象とする。
- 軽量なSVG/CSSで日別棒グラフ・表示期間内の累積時間推移・教科比較・日別正答率を表示する。グラフの値を表でも確認できる。全期間のグラフは直近30日、集計は全履歴と明記する。
- 将来の集中区間追加はセッションの拡張として分離し、今回は実集中時間の確定値を使う。移行時に推測した集中区間は作らない。
- 境界・加重集計・編集・削除復元・移行原文・失敗・競合の単体テストと、PC/スマホ/通常ChromeのE2Eを追加する。既存回帰も実行し、報告書を作成してfeature branchをpush・PR作成する。mainへマージしない。
