## JSON取り込み・復元

### 操作

PCのサイドバーとスマホのフッターに「データを読み込む」を追加した。確認ダイアログでファイルを選択すると、保存形式、記録件数・削除済み件数、開始日の期間、教科名・3階層の項目数、追加記録数、重複スキップ数、既存へ統合する項目数、新規項目数、統合できない項目・競合数を表示する。競合数は問題のある取り込み元項目数で、同じ項目の複数理由はまとめて表示する。プレビュー・キャンセルでは保存データを変更しない。

「バックアップを書き出す」による手動ダウンロードは任意。省略・ダウンロード失敗時にも、競合がなく追加できる内容があれば確認して取り込める。ただしブラウザ内の原文自動退避は必須で、退避に失敗すれば保存しない。プレビュー対象の現在ドキュメントとrevisionを固定し、現在データが更新された場合は確定を無効にする。「最新データで再確認」で更新後の件数・統合先・競合を確認してから確定する。手動ダウンロードのブラウザ／OS上の完了は保証できないため、保存先を確認するよう画面に明記した。

スマホではダイアログ内を縦スクロールでき、確認・キャンセル操作を下端に固定した。保存・検証エラーはダイアログ内に表示し、入力ファイルのプレビューを保持して再試行できる。新しいファイルを選んだ場合は前のプレビューとバックアップ確認を無効にする。読み込み中に別ファイルを選択した場合も古い読み込み結果を採用しない。

### 方式・重複・競合

| 対象                         | 方針                                                                                             |
| ---------------------------- | ------------------------------------------------------------------------------------------------ |
| 保存済みセッション           | 新しいIDを追加。開始・終了・実集中時間・問題数・メモ・作成／更新日時・当時の名称・削除状態を保持 |
| 同じ記録ID                   | 更新日時・内容・削除状態にかかわらず現在データを優先しスキップ。内容差があればプレビューで通知   |
| 現在タイマーと同じ記録ID     | 保存時のID衝突を防ぐためスキップ                                                                 |
| 削除済みセッション           | 新しいIDは墓標付きで追加。同じIDの既存墓標は保持し、古いバックアップから復活させない             |
| 同じ項目ID                   | 改名前の名称でもIDを優先。現在の名称・アーカイブ・順序を保持。階層／変換後の親の不一致は全件中止 |
| 異なるIDの同名項目           | 同じ階層・変換後の親ID・`normalizeName`が一致する唯一の既存項目へ統合。既存IDを維持              |
| 親の異なる同名項目           | 別項目として保持。親子IDを対応表で変換し、兄弟項目の末尾へ追加                                   |
| 一致しない新しい項目         | 元のID・名称・アーカイブ・時刻を保持し、変換後の親に追加                                         |
| アーカイブ済み項目との統合   | 親のアーカイブも含めてプレビューで通知し、現在の状態を保持                                       |
| 曖昧な同名候補               | 対象名・ID・理由を通知して全件中止。新規同名項目のIDもファイル順では決めない                     |
| テンプレート識別子           | 同じ統合先へキーを合併。既存キーの所有者は移動しない。別統合先との競合は全件中止                 |
| ファイル内タイマー・選択状態 | 取り込み対象外と画面に明記。現在のタイマー・選択を維持                                           |

追加取り込みと既存重複のスキップを組み合わせた。全置換・新しい更新日時による上書きは既存データ保全のため採用していない。バックアップJSONの復元も同じ追加方式であり、既存記録の以前の内容への巻き戻しは行わない。削除済み記録の復元は従来の履歴画面で行う。追加対象がない場合は確定できない。

統合は教科→中項目→小項目の順に計画し、取り込み元ID→統合先IDの対応表を作成する。名称は既存の `normalizeName`（trim＋NFKC）で比較する。新規項目の親IDと追加記録の学習項目IDのみ変換し、記録UUID・当時の表示名スナップショット・既存記録・既存項目IDは変更しない。既存項目に新しいテンプレートキーがあれば一意所有を検証して合併し、当該項目の更新日時を進める。キー追加だけの場合も通常の排他・バックアップ・revision更新を経由する。変更がなくなった再取り込みでは保存もrevision更新もしない。

統合計画は入力を変更せずにメモリ上で作成する。衝突が一つでもあれば保存候補を返さず、記録も項目も追加しない。候補を確定できる場合は親子関係・テンプレートキー一意性・全記録の項目参照を検証し、確定処理でドキュメントスキーマも再検証する。

### v1／v2／v3の方針

| 保存形式                             | 取り込み方法                                                                                      |
| ------------------------------------ | ------------------------------------------------------------------------------------------------- |
| v1                                   | Phase 1スキーマを検証し、既存の決定的なv1→v2→v3変換をメモリ上で実行。自由入力の分類へ安定IDを付与 |
| v2                                   | Phase 2スキーマを検証し、削除墓標をnullで補ってv3へ変換                                           |
| v3                                   | 現行スキーマ・親子参照・記録ID重複・時刻を検証して使用                                            |
| 未知バージョン・破損JSON・不正schema | 取り込まず明示的なエラー。現在データを初期化しない                                                |

UTF-8 BOMに対応する。ファイル上限は5MB、記録10,000件、学習項目2,000件。旧形式変換後も項目数上限を検証する。元ファイルを書き換えず、旧形式であればプレビューに変換を明記する。元ファイルは取り込み後も保管する。

## バックアップ・排他・保存の保全

- 確定は既存のAppStore経由で、実際のWeb Locks所有権とプレビュー時revisionを検証する。Repositoryも保存直前のrevision・本体原文一致を検証する。
- Repositoryは現在データのJSON原文を `pomolog.backup.import.<UUID>` に自動退避し、保存内容を読み戻して照合した後、一度の本体書き込みで取り込みを確定する。未保存の新規環境では空の現行ドキュメントを退避する。
- 退避キーは原文から決定し、同じ原文の再試行でバックアップを複製しない。キーが存在する場合は原文一致を確認し、異なる値なら上書きせず中止する。
- 自動移行用の `pomolog.backup.v1.*`／`v2.*` と分離し、過去のバックアップを削除・上書きしない。
- バックアップ作成・照合・本体保存に失敗した場合は現在データを確定変更しない。バックアップ後に外部更新があった場合も本体の上書きを拒否する。
- 取り込みファイルの進行中タイマー・revisionを現在データへコピーしない。正常取り込みのrevisionは一度だけ増加する。
- 実ユーザーの保存領域は操作せず、自動試験専用のデータ・プロファイルで検証した。

## 既知の制約

- 同じIDの記録・マスターを過去の内容へ戻す全置換／巻き戻しは未実装。進行中セット・選択状態の復元も対象外。追加方式の範囲を画面・READMEに明記した。
- 異なるIDでも日時・内容が似ている記録は自動的に同一とは扱わない。別端末由来の独立IDは別記録として追加する。
- 異なる項目IDで名称も異なる場合は、過去の改名関係を推測しない。同名候補が複数ある場合やテンプレート識別子の所有者が競合する場合は利用者による元データの整理が必要で、自動選択・キーの移動は行わない。
- ファイルサイズ・件数上限を超える大規模データの取り込みは対象外。バックアップ用と本体用の空き容量が必要で、容量不足時は中止する。自動バックアップを自動削除しない。
- ブラウザ内のバックアップは同じoriginにあるため、ブラウザデータ消去への備えはダウンロードJSONの外部保管が必要。ダウンロードのOS上での完了をアプリは確認できない。
- 既存PWA／faviconの表示更新時期はブラウザ・OSのキャッシュに依存する。iOS実機のホーム画面アイコン・OS通知・Safariは今回の自動検証範囲外。
- クラウド同期・Firebase・全置換の競合解決は後続Phase。PRはレビュー待ちとし、自動マージを設定しない。
